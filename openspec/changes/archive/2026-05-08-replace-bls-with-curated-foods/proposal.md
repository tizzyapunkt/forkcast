## Why

The BLS 4.0 dataset is unsatisfying as the backbone of forkcast's ingredient search: names are inconsistent (mixed Latin terms, comma-suffixed forms, technical wording), there are no synonyms or aliases, and per-piece weights are absent — which forces the AI recipe importer to estimate every count-based ingredient from scratch even for staples we cook with daily. We want a small, curated, AI-seeded database of raw foods we actually use, with rich names, synonyms, and reference piece weights, so that search feels natural and the recipe importer can match imprecise wording reliably.

## What Changes

- **BREAKING:** Remove the BLS ingredient source: drop the BLS CSV (`backend/BLS_4_0_Daten_2025_DE.csv`), the build script (`backend/scripts/build-bls-data.ts`), the `data/bls.json` artifact, the BLS domain code (`src/domain/bls/`), the BLS scoring (`src/domain/ingredient-search/score-bls-match.ts`), the BLS infrastructure adapter (`src/infrastructure/ingredient-search/in-memory-bls.service.ts`), and the `'BLS'` literal from the `IngredientSource` union.
- Introduce a new `'FOODS'` ingredient source backed by an AI-seeded, hand-reviewable JSON artifact (`backend/data/foods.json`) of ~100–150 raw whole-food entries (vegetables, fruits, meats, fish, eggs, dairy, basic grains/legumes).
- Each FOODS entry carries: a stable id, a canonical German display name, a synonyms list mixing German and English aliases, macros per 100 g, a reference unit (`g` for solids, `ml` for liquids), and an optional list of named piece weights (e.g. `[{ label: "klein", grams: 80 }, { label: "mittel", grams: 110 }, { label: "groß", grams: 150 }]`).
- Introduce an AI-driven build script (`backend/scripts/build-foods-data.ts`) that takes a curated input list of food keys and calls Claude via the existing Anthropic SDK to produce the foods.json artifact deterministically. The artifact is committed to the repo; rerunning the script refreshes/extends it.
- Replace the BLS in-memory adapter with an `InMemoryFoodsService` that loads `foods.json`, indexes canonical name + synonyms (case- and diacritic-folded), and serves search via the existing `IngredientSearchService` port. Synonyms participate in scoring at the same tiers as the canonical name.
- Update the source-toggle capability: in the frontend search drawer the **default source flips from local-catalog-only to OFF-only** (previously BLS was on by default and OFF was an opt-in toggle; now OFF is the always-on default and FOODS becomes the opt-in toggle). The backend HTTP default for `?sources=` (when the parameter is absent) changes from `['bls']` to `['off']` to match. The `sources` query param accepts `foods` instead of `bls`. The search-panel toggle is now labelled FOODS, defaults to disabled, and persists under a renamed localStorage key `forkcast:foods-enabled`.
- Update the AI recipe importer's ingredient matching to explicitly request the FOODS source (`searchByName(name, new Set(['FOODS']))`) rather than relying on the now-OFF-leaning HTTP default. The importer's spec-level contract is unchanged (it still matches against the curated catalog via `IngredientSearchService`), but the implementation pins the source so the drawer's UX-driven default flip cannot accidentally redirect importer matches to OFF.
- Frontend: rename the result badge from `BLS` to `FOODS` and update its visual styling. Update the unique key prefix from `BLS:${id}` to `FOODS:${id}`.
- Tests across backend (`in-memory-bls.service.test.ts`, `score-bls-match.test.ts`, `composite-ingredient-search.service.test.ts`, `parse-bls-csv.test.ts`, `map-bls-entry.test.ts`, `search-ingredients.handler.test.ts`, `import-recipe-from-photos.use-case.test.ts`, `import-recipe-from-photos.handler.test.ts`) and frontend (`search-panel.test.tsx`, `use-search-ingredients.test.tsx`, `search-ingredients.test.ts`) replaced or updated.

## Capabilities

### New Capabilities

- `curated-foods-source`: A locally-bundled, AI-seeded, in-memory food database covering the raw whole foods we actually cook with. Each entry has a canonical German name, a synonyms list, per-100g macros, a reference unit, and optional named piece weights. Search is case- and diacritic-insensitive, scores canonical and synonym matches with the same tiered ranking the BLS source used, and serves results through the shared `IngredientSearchService` port.

### Modified Capabilities

- `bls-ingredient-source`: All requirements removed — capability is retired in favor of `curated-foods-source`. The bundled CSV, build script, JSON artifact, domain code, infra adapter, and `'BLS'` source literal are deleted.
- `ingredient-search-source-toggle`: The default source flips. Backend default (when `?sources=` is absent) changes from `['bls']` to `['off']`. The `sources` query parameter and the `IngredientSource` union accept `foods` instead of `bls`. The search-panel default now shows OFF results and exposes a FOODS toggle (previously default-BLS with an OFF toggle). The localStorage key is renamed from `forkcast:off-enabled` to `forkcast:foods-enabled` and its semantics flip (now opts FOODS in, defaults to false).

## Impact

- **Code (backend):** removes `src/domain/bls/`, `src/domain/ingredient-search/score-bls-match.ts`, `src/infrastructure/ingredient-search/in-memory-bls.service.ts`, `scripts/build-bls-data.ts`, and `data/bls.json`. Adds `src/domain/foods/` (entry types, name+synonym indexer, scorer, mapper), `src/infrastructure/ingredient-search/in-memory-foods.service.ts`, and `scripts/build-foods-data.ts` plus a curated input list `scripts/foods-seed-keys.ts`. Updates `src/domain/ingredient-search/ingredient-search.service.ts` (`IngredientSource` union), `src/domain/ingredient-search/types.ts` (`source` discriminator), `src/infrastructure/ingredient-search/composite-ingredient-search.service.ts` (default sources, branch wiring), `src/http/ingredient-search/search-ingredients.handler.ts` (`sources` parsing), and `src/index.ts` (bootstrap wiring).
- **Code (frontend):** updates `src/api/search-ingredients.ts`, `src/queries/use-search-ingredients.ts`, `src/features/log-ingredient/search-panel.tsx` (toggle label + default state + localStorage key flipped), and result-badge rendering to use `FOODS` instead of `BLS`.
- **Data:** adds `backend/data/foods.json` (committed). Removes `backend/data/bls.json` and the BLS CSV. Adds a curated seed-keys list to `backend/scripts/`.
- **APIs:** `GET /search-ingredients?sources=…` accepts `foods` instead of `bls` (BREAKING for any existing client URLs that pin `sources=bls`). The default applied when the parameter is absent flips from BLS-only to OFF-only. Result objects' `source` field becomes `'FOODS' | 'OFF'` instead of `'BLS' | 'OFF'`. Endpoint paths and shapes are otherwise unchanged.
- **Dependencies:** no new runtime dependencies. The build script reuses the existing `@anthropic-ai/sdk` already wired for the recipe importer.
- **Operational:** the build script requires `ANTHROPIC_API_KEY` at run time (consistent with the recipe importer); it is not invoked at server startup. The runtime backend has no AI dependency for FOODS search.
- **Specs:** retires `bls-ingredient-source`, modifies `ingredient-search-source-toggle`, adds `curated-foods-source`. `ai-recipe-import` is unchanged at the spec level (the catalog port is the same).
