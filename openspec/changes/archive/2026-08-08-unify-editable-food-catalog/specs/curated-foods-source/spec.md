# curated-foods-source — delta

This capability is removed in full. The immutable, build-script-generated FOODS dataset is replaced by the single runtime-editable catalog described in `food-catalog`. Its search, ranking, result-shape, badge, and barcode requirements carry over there restated against `source: 'CATALOG'`; its build-pipeline requirements cease to exist entirely.

## REMOVED Requirements

### Requirement: Curated foods dataset is loaded as a searchable in-memory ingredient source

**Reason**: The dataset is no longer a read-only artifact baked into the image. It becomes the runtime-writable catalog (see `food-catalog` → "Catalog is a runtime-writable store loaded at startup"), which the user edits from inside the app.

**Migration**: The current `backend/data/foods.json` becomes the bundled starting point installed into the data volume only when no catalog exists yet. Load-time validation and the skip-with-warning behaviour are preserved by the catalog store; no data conversion is needed, the entry shape is unchanged.

### Requirement: Each food entry has a canonical name, synonyms, macros, unit, and optional piece weights

**Reason**: Restated verbatim as the catalog entry shape (see `food-catalog` → "Catalog is a runtime-writable store loaded at startup"), extended with a uniqueness rule on `id` because entries are now created at runtime.

**Migration**: None — the entry shape (`id`, `name`, `synonyms`, `unit`, `macrosPer100`, optional `pieces`, optional `untracked`) is byte-compatible.

### Requirement: FOODS name search is case- and diacritic-insensitive across canonical name and synonyms

**Reason**: Replaced by the identical requirement on the catalog (see `food-catalog` → "Catalog name search is case- and diacritic-insensitive across canonical name and synonyms").

**Migration**: None. The folding helper is retained and reused by the catalog scorer.

### Requirement: FOODS search results carry source attribution and macros

**Reason**: Replaced by the equivalent catalog requirement with `source: 'CATALOG'` instead of `source: 'FOODS'` (see `food-catalog` → "Catalog search results carry source attribution and macros").

**Migration**: API consumers must update any comparison against `source === 'FOODS'` to `source === 'CATALOG'`. Macro derivation, `unit`, and the `untracked` pass-through are unchanged.

### Requirement: FOODS search results are ranked with canonical-over-synonym tiering

**Reason**: Replaced by the identical requirement on the catalog (see `food-catalog` → "Catalog search results are ranked with canonical-over-synonym tiering").

**Migration**: None — the scorer, tier values, and token-boundary definition are retained unchanged.

### Requirement: FOODS search ties are broken by canonical name length, then locale order

**Reason**: Replaced by the identical requirement on the catalog (see `food-catalog` → "Catalog search ties are broken by canonical name length, then locale order").

**Migration**: None.

### Requirement: FOODS search result count is bounded

**Reason**: Replaced by the identical requirement on the catalog (see `food-catalog` → "Catalog search result count is bounded").

**Migration**: None — the cap of 20 results is unchanged.

### Requirement: Curated dataset is generated by an AI build script with a curated key list

**Reason**: The generate-from-seed-keys pipeline is the root of the round trip this change removes. Foods are now created in the app — by hand, by the optional AI fill in the catalog manager, or by confirming a resolution during import — and persist directly to the catalog.

**Migration**: Delete `backend/scripts/build-foods-data.ts`, `backend/scripts/build-foods-helpers.ts`, `backend/scripts/foods-seed-keys.ts`, their tests, and the `build:foods` package script. The current `backend/data/foods.json` is retained as the bundled starting point; it is no longer regenerated. The `pnpm --filter @forkcast/backend build:foods` line in `CLAUDE.md` is removed. The AI drafting module is retained for the runtime resolve flow and the catalog manager's fill action.

### Requirement: Curated dataset includes the user's seasoning, herb, and spice shortlist

**Reason**: There is no seed-key list left to make guarantees about. The seasoning, herb, and spice entries already exist in the starting-point catalog and are now maintained like any other entry.

**Migration**: None — those entries (`salz`, `pfeffer`, the herb and spice set, all `untracked: true`) ship in the starting point and remain searchable. They can now be edited or deleted by the user.

### Requirement: Barcode lookup remains OFF-only

**Reason**: Restated against the catalog (see `food-catalog` → "Barcode lookup remains Open Food Facts only").

**Migration**: None — barcode behaviour is unchanged.

### Requirement: Frontend renders source-attribution badge per result

**Reason**: Restated with the narrowed source set (see `food-catalog` → "Frontend renders a source-attribution badge per result").

**Migration**: The `FOODS` and `USER` badge variants are replaced by a single `CATALOG` variant. The `${source}:${id}` list key is unchanged.

### Requirement: Generic search-result shape enumerates the supported sources

**Reason**: Restated with the narrowed discriminator (see `food-catalog` → "Search-result source discriminator enumerates the supported sources").

**Migration**: **BREAKING** — `source: 'FOODS' | 'USER' | 'OFF' | 'SCAN'` becomes `source: 'CATALOG' | 'OFF' | 'SCAN'`. Update every literal and comparison in the backend search services, the import matcher, the resolution flow, and the frontend badge and picker code.

### Requirement: Augment build script promotes the user-foods overlay export into the curated catalog

**Reason**: Promotion exists only to move confirmed foods from the write-only overlay into the immutable dataset. With one editable catalog there is nothing to promote — a confirmed food is already in the catalog the moment it is confirmed.

**Migration**: Delete `backend/scripts/build-foods-augment.ts`, `build-foods-augment-helpers.ts`, `build-foods-augment-overlay.ts`, their tests, and the `build:foods:augment` package script. Existing overlay content is folded into the catalog by the one-time migration in `food-catalog`.

### Requirement: Augment script keeps a per-item human-in-the-loop for promotion

**Reason**: The script it governs is deleted. The human-in-the-loop moves into the app: entries are reviewed in the resolve sheet at confirm time and remain editable in the catalog manager afterwards.

**Migration**: None — no equivalent CLI prompt survives.
